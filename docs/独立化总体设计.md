## 〇、不动的东西（目标方向逐条确认）

| 我们的资产 | 独立化之后 |
| --- | --- |
| 使命：能寄宿灵魂的躯壳；「给骨架不给家」 | **字面完成式**——账本和识是骨架，DSH 从「家」降级为「现在的住所」 |
| 三条不变量（只增不改 / 衰减读时算 / 淡按住不删） | 原样，写进 core 的账本协议 |
| 显式动作族（三问闸门 / vikarma / narrate / transform） | 原样——core 的命令面，系统只给时机 |
| 四路真实信号 + 熏习 + 慢钟三层 | 原样进 core；方向五的缘聚合将来在 core 上做，无 ctx 更纯 |
| 只说感觉不报数字 / 无数据不挂段 / 系数不进口 | 原样，跟着 core 和面板走 |
| 八向清单 | 全保留；独立化不改写任何一个方向，只换它们住的地基 |

**关键认知：这不是重写，是归位。** `lib/memory.js` 头注写着「纯函数，不碰文件、不看时钟（now 一律当参数）」——activation/fit/search/fast/intent/emotion 全是同款纪律。核早就存在，只是被 index.js（DSH 适配器）抱在怀里。独立化 = 把抱着的放下来。

## 一、目标架构：四层，依赖只准向下

```
┌─────────────── 适配层（可替换的「家」）───────────────┐
│  dsh-remember（九工具/七段/设置页 → 转译成核调用）      │
│  未来的壳：CLI、独立面板、别的宿主、QQ/微信通道          │
└──────────────────────┬───────────────────────┘
                       │ 窄 API（进程内 import 或本地 HTTP）
┌──────────────────────┴───────────────────────┐
│ 服务层  shihai-service（L2，可选常驻进程）       │
│  心跳·叫醒判定·健康自检·事件出口·本地鉴权         │
├──────────────────────────────────────────────┤
│ 运行时层  shihai-runtime                        │
│  家目录解析（SHIHAI_HOME ?? DSH_HOME 兼容）      │
│  进程缓存 · 文件锁 · logger 注入                 │
├──────────────────────────────────────────────┤
│ 核  shihai-core（L1，零依赖，不知道 DSH 存在）    │
│  memory / activation / fit / search / emotion / │
│  fast(+状态推导) / intent / stream / 账本协议     │
└──────────────────────────────────────────────┘
```

**层间新不变量（进 philosophy + ADR）：**

1. core 不 import 上层任何东西；core 的词汇表里没有 DSH
2. runtime 不 import service/适配层
3. 适配层单向向下；跨层只走窄接口
4. 全链零依赖（除 Node 内置）——「轻」从习惯升级为架构约束
5. 账本协议属 core：append-only 原语、游标推进、坏行告警、备份拒写、索引维护——这些是**识的肉体规则**，不是宿主适配

## 三、服务层（L2）接口契约

本地 HTTP（127.0.0.1:**12741**，写进 ADR），Node http 模块，零依赖：

```
POST /remember  {text,kind,weight,四问,refs,tags,context,audience}   → 账本写（显式动作族规则原样）
GET  /recall    ?q=&limit=&kind=&audience=                           → 条目+origins+echo 记账
POST /narrate | /transform | /vikarma | /forget                      → 三个动作 + 淡/按住
GET  /sections                                                       → 七段文本（任何宿主拉去注入 system prompt）
GET  /status                                                         → 现有投影（全内存口径不变）
GET  /health                                                         → 三项自检：进程在/账本可写/游标新鲜（抄小鲸鱼 8848 功课）
GET  /events?since=                                                  → 增量事件（未来通道用）
```

- **鉴权从第一天就有**：启动生成 token 存 home，头 `X-Shihai-Token`——本机服务也不裸奔
- **调用方声明受众**：「这一轮谁在听」由适配器显式传（solo/private/group:号），服务不猜——判定函数单一
- **关 DSH 验收**：服务照活——账照长、瀑流每天生成、curl 全流程可走。这一刻「独立运作」成立

## 四、适配层瘦身后的样子

`dsh-remember/index.js` 从 ~4200 行降到估 ~600 行：启动时定家目录 → 注册九工具（schema/回执**逐字不变**）→ 段注入（拉 /sections 或进程内 core 调用）→ wake 回调注册。client.js 数据面不变。

**双模式**：`mode: 'inline' | 'service'`——inline = 进程内 import core（DSH 现状最稳，v1 默认）；service = 走 HTTP。两者共用同一 core API，适配器永不直碰协议层（防分叉）。

## 七、在生态地图上的位置

《数字生命项目群·全量评析与对比报告》说五家是「同一条命的器官层级」：**汐造人，Whale Card 造卡，大肥鱼定规矩，识海造器官，万卷管卷轴**。独立化之后，识海还是那个最轻的器官——但它不再问「装在哪」。
