# 识海改动审核清单（对照《Amikar 完整功能与实现说明书》v0.2）

> 2026-11-25 立。职责：lead 审核识海项目的每一次改动，判据 = 说明书的大体设计与方向。
> 本清单是量尺的落地形态；说明书自身只增不改，本清单随其修订追记。

## 十查（每次改动逐条过）

1. **三条不变量**（§一）：只增不改（账本文件）/ 衰减读时算（不写回）/ 淡按住不删——任何改动不得违反；删账、改旧行、写回衰减值 = 一票否决
2. **四层纪律**（§三）：core/ 零依赖不知 DSH（grep `'dsh'` 应 0）；账本协议归 core/protocol；适配面在 index.js；runtime/service/adapter 分层不被抄近路
3. **考卷门**（§九）：检索/账本相关改动跑冻结卷——**R@5 ≥ 0.888 且 MRR ≥ 0.689 且负题 0**（B−0.05 全口径，不只 R@5）；逐数一致才放行
4. **G-1 验收范式**（§九）：重构类改动必须特征测试先行（钉死现行为再动手）→ 原样迁移 → 三重判官（考卷逐题 + 单测 + 真账字节级）全绿
5. **给骨架不给家**（§一/§七）：改动不得把「家」焊死在 DSH——家目录解析 `SHIHAI_HOME ?? DSH_HOME` 兼容不得破坏；新路径不得硬编码 DSH 专属假设
6. **安全红线**（§八）：不碰她的账本文件（工具写路径越权 = 否决）；令牌/密钥不进文档、回执与日志；不可逆操作必须可退
7. **隐私**（§十二）：新文档/新输出不得含 QQ 号/真名/生日/聊天原文/令牌/含用户名的绝对路径；文件名含号码的册子不进分享面
8. **常数带档位**（头部纪律 + 附录）：新常数必须标 量测/推导/约定/裁量 + 出处，并进附录档位表；把裁量标成量测 = 一票否决
9. **接口唯一与契约冻结**（§四/§十一）：prompt 段唯一出口（/sections 带受众参数，不另设）；事件对象/任务对象的字段不私自扩改（冻结期变更须评审）
10. **性格与回话纪律**（§四 OS 收编清单）：改动不得静默改变已入账的性格（简洁白话/只说要说的话/沉默合法/看见不等于要回应）——纪律要么收编成规则，要么显式记「放弃」

## 流程

改动 → 本清单十查 → 三重判官（考卷逐数 + 单测点名 + 真账前缀/hash）→ 通过后走 GitHub Desktop 内嵌 git 推送（真历史；REST 仅应急）→ 重载后探针旗标记录。
