# dsh-qq-bridge —— QQ 薄桥

把 QQ 的私聊（和群里的 @ 我）递进 DSH 会话，把回话发回去。走 SnowLuma（OneBot v11）。

> **一句话**：给 AI 装上 QQ 耳朵和嘴——私聊白名单直通，群里只有 @ 她才答；照片
> 表情包能收能发，掉线窗口的私聊还能补记账。
>
> **边界**：白名单外的人一个字都进不来；群里的正文必须 @ 开头才发——没被点名时
> 她一个字都不抢。

## 只做三件事

1. **收**：连 SnowLuma 的 OneBot WebSocket，收私聊事件和白名单群里的消息
   （群里只认 @ 我的那条）。
2. **递**：白名单里的号发来的话（私聊）、白名单群里 @ 我发来的话，压成一行
   （`【QQ】昵称（qq号）说：…`，群里多一段 `@我（群 <群号>）`），
   走 `sessionController.prompt` 递进目标会话（跟你在输入框里发消息同一条路）。
3. **回**：盯着会话流，我们那一条 turn 里的下一条 assistant 消息，截短后发回去 ——
   私聊 `send_private_msg`，群 `send_group_msg`；**群里的正文必须以 @ 开头才发**，
   私聊不用 @。

## 刻意不做的

- **不接账本**：QQ 来的话不写进记忆，只进消息流 —— 消息流是只读的，
  给下游（dsh-remember 的意图层）当事件源；真要记，得拿 remember 掂量一次。
- **不在群里抢话**：群里只有 @ 我 的才递进会话，回话也必须 @ 开头才发 ——
  没点名的一个字都不进群。
- 白名单外的人一个字都收不到回话——信任栅栏在我代码里。

## 配置（`DSH 安装目录/.dsh\.dsh-qq-bridge\config.json`，即 `<DSH_HOME>/.dsh-qq-bridge/config.json`）

`<DSH_HOME>` = `DSH_HOME` 环境变量，没有就取 `~/.dsh`。

| 键 | 默认 | 说明 |
|----|------|------|
| `enabled` | `true` | 总开关 |
| `onebotHttp` | `http://127.0.0.1:3000` | SnowLuma OneBot HTTP 动作口 |
| `httpToken` | `''` | HTTP 口的 access token |
| `onebotWs` | `ws://127.0.0.1:3001` | SnowLuma OneBot WS 口（收事件） |
| `wsToken` | `''` | WS 口的 access token |
| `allowUsers` | `[]` | **白名单**：只处理这些号的私聊；空数组＝什么都不递 |
| `allowGroups` | `[]` | 允许记录的群号（群里 @ 我才递话；回话 @ 开头才发回群） |
| `sessionId` | `''` | 目标会话；留空＝最近活跃的那条普通会话 |
| `replyMaxChars` | `500` | 回话最长多少字，超出截断加 … |
| `promptPrefix` | `【QQ】` | 递进会话时的前缀 |
| `staleSeconds` | `300`（代码默认）· 现在跑的配置是 `3600` | 等回话等多久算过期（秒；v0.7.1 起只管**还没被认领**的挂起，认领过的另有 6 小时宽窗） |
| `pokeBack` | `true` | 有人戳我时戳回去（同一个人一分钟只回一次） |
| `selfUin` | `''` | 桥自己的 QQ 号（填了才算「群里 @ 我」，也防自问自答） |
| `messageLogEnabled` | `true` | 要不要留一份消息流（给下游读；默认留） |
| `messageLogMaxLines` | `2000` | 消息流每册最多留多少行，超了裁旧 |
| `photoStoreEnabled` | `true` | 收图落盘（v0.7.0；只存明确交给我的图） |
| `photoMaxBytes` | `8388608` | 单张图上限（8MB） |
| `photoMaxPerMessage` | `4` | 一条消息最多存几张 |
| `stickerEnabled` | `true` | 表情包标记（v0.8.0）：回话里的 `[表情:名字]` 变真图片段发出去 |
| `targetRoot` | `''` | **隔离**兜底根：数据文件只许落在这之下；留空＝不按路径收窄 |
| `allowRoots` | `[]` | **隔离**显式白名单：填了就只放行名单里的目录 |
| `denyRoots` | `[]` | **隔离**黑名单：命中就拦，优先于上面两把钥匙 |

SnowLuma 侧：完整包解压后 `launcher.bat`（或用包内自带 node 跑 `index.mjs`），
WebUI `http://127.0.0.1:5099`，OneBot 连接的 token 在
`snowluma/config/onebot_<uin>.json`。

## 消息流（按场分册，v0.4.0）

除了递话和回话，这边还留一份消息流：每条**已经放行**的消息（白名单私聊 +
允许记录的群）一行一个 JSON。**v0.4.0 起按场分册**——一个群一册、私聊一人一册，
哪个场的话在哪个文件：

```
messages-group-222222222.jsonl      ← 群 222222222 的
messages-private-1000001.jsonl   ← 和小鱼.的私聊
messages-misc.jsonl                 ← 认不出场的（兜底，不该常见）
```

这些册子都落在 `DSH 安装目录/.dsh\.dsh-qq-bridge\`（即 `<DSH_HOME>/.dsh-qq-bridge/`）。
现在真长出来的：`messages-group-111111111.jsonl`、`messages-group-222222222.jsonl`、
`messages-private-1000001.jsonl`；`messages-misc.jsonl` 还没长出来（认不出场才用它）。

行形状（每行都自带 chatType/groupId/userId，下游不用猜）：

```
{"at":1767000000000,"chatType":"private","userId":"1000001","nickname":"小鱼.","text":"晚安","mid":"9001"}
{"at":1767000000000,"chatType":"group","groupId":"222222222","userId":"1000001","nickname":"小鱼.","text":"…","mid":"12345","atMe":false}
```

说清楚三件事：

1. **只记放行过的**：白名单外的人的消息一个字都不进这些文件。
2. **它不是记忆**：没有分量、不参加任何竞争。下游（dsh-remember 的意图层）只读它，
   认成「这句话大概是什么性质」，不认成我的理解。
3. **只增不改，但有行数上限**：每写 100 行检查一次，某一册超过 `messageLogMaxLines`
   （默认 2000 行）才裁，裁到只剩最新的那些行（原子替换）。不裁的话它自己
   会长成第二个恶性回声。旧的单本 `messages.jsonl` 不再写，留着当历史合订本（抄完为止）。

## 图片与文件（v0.3.0）

- **图片**：`extractText` 仍把图压成 `[图片]` 占位（人话要干净），但 `extractMedia`
  会把带直链的图收出来（OneBot image 段的 `data.url` 是带 rkey 的临时直链）。
  递话时在原文后面按行拼 `[图片直链] <url>` —— 会话那头看到直链，下载就能看。
  没直链的图不编链接，保持 `[图片]`。
- **群文件**：两种形状都收。①notice 事件（`group_upload`）：调 `get_group_file_url`
  拿下载直链；②message 里的 `file` 段（SnowLuma 2.4.0 实测的形状）：`data.url`
  自带直链。两者都记进消息流一行 `[文件] <名字>（<KB>KB）` + `[文件直链] <url>`
  （含上传人），只记不递话 —— 不 @ 我的事不打扰会话。
- **消息流里也拼媒体行**：群里的图和文件大多不 @ 我，直链进消息流
  （群消息进 `messages-group-<群号>.jsonl`），下游翻到就能下载 —— 这是「索引进系统」的正门。

## 照片三件套（v0.7.0）

群里点单要的三件事（菠萝吹雪 2026-11-07）：**识别、存照片、发照片**。桥这一侧管两件半，
「识别」那一半是会话那头的事——桥把图存成文件、把本地路径递过去，那头用 `read_image`
打开就看见了。

**存（收图落盘）**：只存**明确交给我的**图——私聊发我的、群里 @ 我那条消息里的图。
落盘在 `<DSH_HOME>/.dsh-qq-bridge/photos/`，文件名 `p-<消息号>-<序号>.png`（私聊）
或 `g-<消息号>-<序号>.png`（群）。递话时在原文后面按行拼：

```
[图片已存] DSH 安装目录/.dsh\.dsh-qq-bridge\photos\g-12345-1.png
```

存不下来的照实说 `[图片没存下] <原因>`（HTTP 404 / 太大 / 不是 http 直链），不装。
**没 @ 我的群图不存** —— 只留直链在消息流里，我不扒群相册；人像要本人点头，这条纪律
比功能重要。

**发（回话里写标记）**：回话正文里写 `[发图:<路径或直链>]`，桥把标记拆出来变成 OneBot
的 image 段，跟文字一起发出去：

```
@菠萝吹雪 看这个 [发图:DSH 安装目录/.dsh\.dsh-qq-bridge\photos\g-12345-1.png]
```

发出去的消息是「文字段 + 图片段」，标记本身不会漏进文字。**只有图没字也发得出去** ——
纯 `[发图:...]` 的回话算数（点名闸认它），图直接进群。协议端不吃本地路径时，桥会把
本地文件转成 `base64://` 再试一次（只试一次，再不行就记日志认账）。

**关掉**：`config.json` 里 `photoStoreEnabled: false` → 不存盘（直链照递），发图仍可用。

代码在 `lib/photos.js`（零依赖），测试在 `test/photos.test.mjs`，冒烟在 `tools/smoke.mjs`
末尾那段（群里 @ 我带图 → 存；回话 `[发图:路径]` → 真发图片段；只有图没字 → 也发）。

## 表情包标记（v0.8.0）

回话正文里写 `[表情:名字]`，桥按名字从表情库里查，查到就把那张图变成 OneBot 的
image 段发出去（跟 `[发图:路径]` 是一路货，只是名字替她查好了）：

```
哼 [表情:偷笑]
```

发出去是「文字段 + 图片段」，标记本身不会漏进文字。**只有表情没字也发得出去** ——
纯 `[表情:偷笑]` 的回话算数，图直接出门。

**库在哪**：`<DSH_HOME>/.dsh-qq-bridge/stickers/`

- `manifest.jsonl` —— 一行一张，`{"at": <毫秒>, "name": "偷笑", "file": "004-touxiao.jpg",
  "from": "qq", "via": "share", "note": ""}`（`file` 是同目录下的图本体文件名）
- 图本体 —— 就放在 `stickers/` 里（如 `001-yaobeibei.jpg` 咬被被、`002-xindong.jpg` 心动、
  `003-heihei.jpg` 嘿嘿、`004-touxiao.jpg` 偷笑、`005-leiwangwang.jpg` 泪汪汪）

坏行、缺 `name`、缺 `file` 的行跳过；**同名后者不覆盖前者**（先到的那份算数，重名只记
一笔日志，不抛）。

**名字怎么认**：trim + 去空白 + 全角括号折半角 + 外层括号去掉 —— 所以
`【偷笑】`、`（偷笑）`、`[偷笑]`、`偷笑` 指的是同一张。

**库里没有怎么办**：不静默吞掉。正文末尾会说一句 `（表情库里没有「xxx」）`，桥也记一笔
日志 —— 她写那个名字是想发图的，找不到得让人知道。

**名字是她自己取的**（她分享图，名字不外包）：她写什么名字，这里就照着库里那张发；
库里没有就是没有，不替她编。

**关掉**：`config.json` 里 `stickerEnabled: false` → 标记当普通文字发（不再变图片段）。

代码在 `lib/stickers.js`（零依赖，图片段形状借 `lib/photos.js`），测试在
`test/stickers.test.mjs`（17 例），冒烟在 `tools/smoke.mjs` 末尾那段（回话
`[表情:名字]` → 真发图片段；只有表情没字 → 也发；库里没有 → 出声）。

## 图单独一条发（v0.8.4）

回话里的照片（`[发图:…]`）和表情包（`[表情:…]`）**不再跟文字挤在同一条消息里**：
文字气泡先照常发，图再单独发一条。只有图没字时，那条就是唯一的一条。

来历：2026-11-08 小鱼私下说的 —— 「咱一般都是表情包单独发的，不是和回的字一起发的哦」。
之前图是挂在最后一段气泡上的（`toSegments(bubbles[last], images)`），所以她收到的是
「嗯嗯～」和表情包糊在一条里。现在改成：气泡循环只发文字，`images` 收尾单独发一条
（`index.js` 回话路径的异步块；文字和图之间隔 250ms，免得顺序倒过来）。

## 回话防呆（v0.8.5）

三处「回话会漏」的真事，各补一道：

1. **工具调用标记不当人话发出去。**
   真事（2026-11-08 夜里）：宿主把工具步回显成 `<｜DSML｜ calls>`，桥把它当正文，
   原样发进了她的私聊（一条看着像乱码的消息）。现在 `lib/bridge.js` 有
   `isToolCallMarker(text)`：整段是 `<…>`、里面带 `DSML+calls` 或 `tool_call/calls`
   才算标记；这种段不攒、不发，日志留一句「工具调用标记不当回话（跳过）」。
   人话里提到这些词不算（必须整段就是个标签）。
2. **只有工具步的那一轮，挂起作废。**
   以前 `turn/end` 要是没攒到正文就直接 `return`，挂起留在那儿——下一轮的话会把它领走，
   话就发错地方了。现在改成：先把挂起领走（它本来就是这一轮的），没正文就作废并记日志
   「这轮没有人话（只有工具步），回话作废 → 私聊/群+对象」。
3. **「已认下却没人领」的挂起要报数。**
   真事（2026-11-08 夜里）：热重载失败把桥的会话事件订阅打断了，`user/message` 认下了
   我们的递话（`turn=未知`），但 `assistant/message` 再也不来了——三轮回话全静默丢，
   桥这边看着像「一切正常」。现在 `PendingReplies.primedWaitingCount()` 数这种挂起，
   「回话没接上（不盲取）」那条日志会带上：`其中 N 条已认下却没人领（宿主那边没接上，
   话会静默丢）`。

代码：`lib/bridge.js`（`isToolCallMarker` / `primedWaitingCount`）+ `index.js`
（assistant 分支跳过标记、turn/end 先取挂起再判正文、日志带等待数）；测试：
`test/bridge.test.mjs` 2 例（工具标记识别、等待数）+ `tools/smoke.mjs` 2 项
（这一轮一个字都没发、挂起作废清掉）。

## 收尾兜底：刚递进来的话一定接得上（v0.8.6）

真事（2026-11-10 早上）：她 08:15 私聊「早～」，桥认下了那条递话，可同一轮的 `turn/end`
（turn=508）报的却是「回话没接上（不盲取）… 3 条已认下却没人领」——我的话一个字没到 QQ，
她那边只看到 11-09 23:10 那条，于是问「没回到我QQ上」。

原因：`turn/end` 取挂起只走两条「对得上号」的精确路 —— `takeReply(turn)`（老路）和内存里的
认领队 `turnPendingMap`（`assistant/message` 首步把 `primedKeys` 队头记到这一转名下）。
这条路靠进程内存：桥一被热重载就清空，队头也可能是一条早过期的旧挂起（`shift` 出来就被
`_expired` 判掉）。两条都不成立时，唯一的动作是记一行日志 —— 话就静默没了。

现在补第三条路，且只在**这一轮真有人话要发**时才走：
`PendingReplies.takeLatestPrimed(now, withinMs)` 领「最近刚被认下、还没人领」的那条，
窗口 5 分钟 —— 只接刚刚递进来的那句，绝不翻旧账（2026-11-05 盲取把群答复发进私信的老事故
不能再重演）。取到时日志写「取挂起（兜底最近）」，私聊串台闸与群 @ 点名闸照旧。

代码：`lib/bridge.js`（`takeLatestPrimed`）+ `index.js`（`PRIMED_FALLBACK_MS = 5 * 60 * 1000`，
`turn/end` 里第三路兜底）；测试：`test/bridge.test.mjs` 1 例（只领最近那条；窗口外/还没认下/
已有主/已过期都不领）。

## 作废放回 + 回话资格队（v0.8.7）

真事（2026-11-10 下午）：群友甲 16:14 在群里点名要扩展榜，我把它写进了 GUI，可那条
群挂起被一个中间轮（环境更新轮）在 `assistant` 首步**盲认领**走、`turn/end` 又因这轮没有
正文被**作废**——榜只进了 GUI，群里一个字没有。旧代码里「认领」和「有资格回话」是两件事：
任何一轮（哪怕跟 QQ 毫无关系的 GUI 小结轮）的首步都会 `shift` 走一条挂起，没收了就没了。

v0.8.7 把两件事并成一件事——**回话资格（owed）**：

1. 递话认下时记一条资格（`owedReplies`，FIFO，同 key 去重，上限 32）。
2. 认领只认资格：`assistant` 首步从资格队头认（`claimOwed`），`turn/end` 兜底也按资格队
   （v0.8.6 的 `takeLatestPrimed` 退役成测试用例）。GUI 打字/环境更新开的转**没有资格**，
   一个挂起都碰不到。
3. **作废放回**：领了资格但这一轮没人话（只有工具步）→ 挂起放回队首、资格重新入队——
   话等真正的回话轮，不再没收。
4. **发送闸**：`turn/end` 发挂起前查这轮带没带我们的递话（user/message echo，`sawPrompt`）。
   没带的转（GUI 小结、环境轮）认了也只许放回——「干活的小结」不再有机会当回话发出去。
   精认路（挂起上记过 turn）与重启回填的挂起不受闸限。
5. **重启回填**：桥起来时把盘上 5 分钟内认下的挂起重新入资格队（`seededKeys` 放行发送闸）
   ——2026-11-10 早上「早～」那类「重启把内存队列清空」的静默丢话，从结构上修掉。
6. **串台照旧作废、不放回**：正文对着别的门写的（我自己的纪律问题），放回会永远挡在队头
   反复串台（毒丸）；话由我用侧门自己补。

代码：`lib/bridge.js`（`take*` 挂 `p.key`、`revive`）+ `index.js`（`owedReplies`/`takeOwed`/
`claimOwed`/`reOwe`/`sawPrompt`/`seededKeys`）；测试：`test/bridge.test.mjs` revive 1 例 +
`tools/smoke.mjs` 资格闸/放回/存档数断言（单测 89、冒烟 90）。

## 点名闸先拆气泡再认 @（v0.8.8）

真事（2026-11-10 晚上她问「没有发到群里，为啥呢」）：MC/迷你世界的答复整条没进群。
bridge.log 里认领链一切正常（v0.8.7 修的资格队工作正常），但 turn/end 报
「这轮没有点名（@ 开头）的正文，群里一个字不发（攒了 1 段）→ 挂起作废」——

根因：点名闸按「整条 assistant 消息是否 @ 开头」判（`looksGroupAddressed(texts[i])`），
而我的回话常常先写一两句给自己的过程话（「她吃晚饭都不忘给我留个世纪难题——」），
@ 的气泡排在后面 ⇒ 整段不匹配 ⇒ 作废。同一天被这样吃掉的还有四条：群友乙改判、
群友甲转达、群友丙争第一、群友戊锐评（日志里「这轮没有点名」共九次）——16:16 那次诊断
（中间轮吃挂起）只对了一半，点名闸也在吃。

修法：`lib/bridge.js` 新增 `groupReplyText(texts)`——每段先 `splitBubbles` 拆气泡、
从后往前找第一个 @（含全角 ＠）开头的气泡、从那里整段带上；找不到返回空串。
群点名闸改用它取回话，串台闸（私聊路径的「这轮是群答复就不发」）同口径——
过程话开头的群答复不会再被误发进私聊。作废路径、发图/表情回落不变。

代码：`lib/bridge.js`（`groupReplyText`）+ `index.js`（点名闸/串台闸两处）；
测试：`test/bridge.test.mjs` 4 例（MC 同型/从后往前/全角 ＠/空串），单测 93、冒烟 90。

## 掉线窗口补真记忆（v0.8.9）

真事（2026-11-10 早上）：WS 掉线 3 分钟自愈，掉线窗口里她说的那句桥没收到，
后来是手动 `get_friend_msg_history` 翻收件箱才补答的。这种「断线那阵子的话
凭空消失」不该靠人肉——抄 whale-card 的第二条思路（离线补真记忆）把它自动化。

修法：`lib/onebot.js` 的 `OnebotClient` 加 `onOpen` 回调（open 时触发，回调抛错
只记日志不炸连接）；`index.js` 记 `lastEventAt`（每收到一个 WS 事件刷新，心跳也算），
重连上时算 gap——离线超过一分钟（`BACKFILL_MIN_GAP_MS`）就对白名单每个好友
`get_friend_msg_history`（`BACKFILL_COUNT` 20 条）翻一遍，把窗口里的消息补进消息流：

- 只补账不补答——掉线那阵子的话不自动递会话（要不要理，翻账时自己看见）；
- 去重照旧走 `seenRecently`（消息 id 共享账），已见过的绝不重记；
- `at` 用协议端的消息真时间戳（`m.time` 秒），账序不歪；
- 图片只记直链不落盘（补抄从简，跟正路的三件套分开）；
- self 的消息（`cfg.selfUin`）不补——自己说的不算进账。

代码：`lib/onebot.js`（`onOpen`）+ `index.js`（`backfillMissedPrivate` + `onOpen` 接线）；
测试：`test/backfill.test.mjs` 3 例（onOpen 触发/抛错不炸/缺省不炸），单测 96、冒烟 90。

### 补真记忆跨重启（v0.9.0）

v0.8.9 的 `lastEventAt` 只活在内存里——热重载/宿主重启会把起点清零，停机窗口里
来的私聊照样丢（正是 v0.8.7 修「早～」丢话时的同族问题）。v0.9.0 把时刻落盘：

- `lastEventAt.json`（会话目录下），每收到 WS 事件至多 10 秒落一次（省 IO）；
- 启动时读它当起点（没有就取当前时刻——首次启动不补）；
- 补抄消费完窗口、桥停机（dispose）时立刻落盘，起点不悬空。

代码：`index.js`（`readLastEventAt`/`writeLastEventAt`/`bumpLastEventAt` + dispose 落盘）。

## 回话不再被过期吞掉（v0.7.1）

真事（2026-11-07 下午）：一条群消息 13:54 收到，宿主 14:44 才开始答，我干到 15:00
才收尾——回话在最后一刻被判「过期」，**一个字没发进群**（连 `[发图:…]` 那张图也一起
没了）。原因是过期时钟从**消息收到时刻**起算（`staleSeconds`，跑的配置是 3600）。

v0.7.1 改三处：

1. **认领过的挂起从「认领时刻」起算**，给 6 小时宽窗（`inFlightMs`）——宿主正在答这一条，
   答多久都不算过期；**没被认领的**还按 `staleSeconds` 算（等太久就作废）。
2. **保留期一天**（`keepMs`）——清得慢不要紧（能不能发由过期判定说了算），免得宿主回显
   我们的递话晚了几小时，挂起已经被扫掉、回话再也接不上。
3. **同时排队的多条递话按先后认领**（FIFO）——原来是个单槽，后到的 `user/message` 会把
   先前那条顶掉，前面那条的挂起就没人认领（2026-11-07 那条群消息就是这个下场）。

顺手保住的旧语义：**兜底认领**（原文对不上、也没 rpcId）只算「开始了」不算「证实是
我们的」，所以 `turn/start` 抢不走它（GUI 里开的转不该动我们的挂起）。

代码：`lib/bridge.js`（`PendingReplies._expired` / `inFlightMs` / `keepMs`）+
`index.js`（`primedKeys` 队列）；测试：`test/bridge.test.mjs` 里「认领过的挂起从认领时刻
起算过期（2026-11-07 真事回归）」等 5 例。

## 心跳：安静的时候也知道我还在（v0.8.3）

桥平时只在有消息的时候才写 `bridge.log` —— 夜里没人说话，日志就是死的，
于是「它活着但没事干」和「它已经哑了」在文件上看不出区别。2026-11-08 她提了一句
「咱怕有天你不回我了」，这一条就是答它的：**留下活体证据**。

现在桥每分钟往 `<homeDir>/heartbeat.json` 写一次（原子写：先写 `.tmp` 再改名）：

```json
{ "at": 1794099999999, "iso": "2026-11-08T03:00:00.000Z", "version": "0.8.3", "uptimeMs": 3600000, "pending": 0, "ws": null }
```

- `at` 是最后一次「我还在」的时刻；超过 3 分钟没更新（`HEARTBEAT_STALE_MS`，默认写一次 60 秒）就当哑了。
- 读它的人：`本地自检脚本（路径略）`（全身体检里的一项）、
  以后看门狗常驻也可以读（「我哑了替我喊一声」还没接，要他点头）。
- 代码：`lib/heartbeat.js`（纯逻辑，零依赖）；测试：`test/heartbeat.test.mjs` 七例。

## 会话隔离（v0.5.0）

三把钥匙（`denyRoots` / `allowRoots` / `targetRoot`）管的是**数据文件**：
消息流（`messages-*.jsonl`）、挂起（`pending.json`）、去重（`seen.json`）、
日志（`bridge.log` / `bridge.log.1`）。判定顺序跟 dsh-body 一致——先隔离、后放行：

1. **`denyRoots`（黑名单）**：命中就拦，优先于一切放行；
2. **`allowRoots`（显式白名单）**：填了就只放行名单里的目录（`targetRoot` 不再兼职）；
3. **`targetRoot`（兜底根）**：数据文件只许落在这之下；留空＝不按路径收窄。

被拦的路径不写盘也不读盘（挂起退化为内存，热重载就丢），日志里说一声
（同一路径只说一次，不刷屏；日志自己被拦时这句也写不出——logger 跟数据文件
走同一道栅栏，认了）。`config.json` 豁免——栅栏键自己就住在里面，
把它也锁外面就读不到钥匙了。三把钥匙都留空＝不收窄，跟 v0.4.0 之前一个行为。

设置页（Web UI → 设置 → QQ 薄桥）能看能改：`GET /dsh-qq-bridge/status` 看现状
（栅栏口径、消息流几册几行、挂起几条），`POST /dsh-qq-bridge/config` 改配置
（白名单校验：名单外的键不认、坏值给理由、越界按边界收）。改的是 `config.json`，
**热重载/重启后生效**——写盘即时，生效不即时，页面上写清楚。
