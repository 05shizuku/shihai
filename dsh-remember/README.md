# dsh-remember · 记得

给住在 DSH 里的 AI 一本自己的账。

> **一句话**：她说过的、认下的，写进一本只增不改的账本；每条带分量，重的忘得慢；
> 找的时候按分量加契合度翻，不靠向量库。
>
> **举个例子**：你说「以后别给我安排熬夜的活」，它记成一条带分量的账；半年后你再
> 提起熬夜，它还能翻出这条原话和当时掂量的分量。

它不接管任何别的记忆系统：不同的插件各记各的账，按各自的家目录走，互相读得到
文件，但谁也不算谁的记忆。这本账用「我」的口吻写 —— 记东西的是 AI 自己，
掂量分量的也是它。

身体那边秒级发生的事（吃了饭、错过一顿、心里动了一下）由 dsh-body 写在它自己家里，
这本账只读抄一份、不变成记忆节点 —— 要变成「我记得的」，得我回头掂量一次
（见下面「快层接缝」一节）。

## 它记什么，不记什么

**记**：一件事本身（原话），加上我当时的判断 —— 它有多重、改变了我什么、跟旧的对上
还是撞上、我会不会因此做得不一样。附件是几个词和几条旧条目的 id。

**不记**：任何「读数」。这里没有亲密度、没有好感度、没有进度条。分量 0–1 是我写下来
的判断，不是仪表盘；设置页也**没有**改某个节点分量的入口 —— 那是账本的规矩，不是面板
的旋钮。

## 三条不变量

1. **原话层只增不改。** `lines.jsonl` 一行一条，写进去就一直在。节点可以被调轻、被按住，
   原文不会消失。
2. **衰减只在读的时候算。** `weight_eff = weight × exp(-days/τ)`，`τ = 2 + 28 × weight` 天。
   不跑后台任务，账本本身不被时间改 —— 同一天重放，永远同一个结果。
3. **淡不等于删，按住也不等于删。** `forget` 只有 `fade` / `seal` / `restore`，没有删除。

## 写入三问

`remember` 有三个可选的自问：

| 参数 | 问的是 |
| --- | --- |
| `changes` | 这件事改变了我什么 |
| `conflicts` | 跟旧的对上了，还是撞上了 |
| `will_do` | 我会不会因此做得不一样 |

三问一条都没答也能存（原话层永远收），但**不会被挂到明天开头**。回执里会写明这一点。
这是刻意的：不能什么都往意识里塞，否则等于什么都没记。

> 在好奇上，这三问换义：`changes`＝知道了会改变我什么、`conflicts`＝跟什么撞上了、
> `will_do`＝下一步打算怎么试（见下面「好奇表」一节）。

> 真机事实（2026-11-02 00:00）：这条规矩之前只写在文档里，渲染那一层其实没兜住 ——
> 没答三问的条照样能挂进开头（只是分量不够高时排在后面，看不出来）。现在 `renderSection`
> 的候选池按 `hasThought` 过滤了，「没结的那一栏」也一样。翻得到跟挂得上是两回事：
> 没答三问的条仍然在账本里，`recall` 问得具体照样捞得回来。

## 「我」—— 自我那一格

账本里另有一格不是「发生过什么」，是「我现在是这样」。它有三个种子槽位
（`identity` 我是谁 / `cares` 我在意 / `refuses` 我不做），槽位也可以自己长新的。
写同一个槽位的新值，旧的那条**退下**（`superseded`：不删、`recall` 翻得到，只是不再
在开头跟我自己顶嘴）。

- 走**慢钟**：`τ = 30 + 270 × weight` 天（weight 1.0 ≈ 300 天淡一半）。信念的更新率是月级的，
  不该跟「今天发生了什么」一样按天掉。
- 一个槽位只自称一条；分量淡到 `SELF_MIN_WEIGHT`（0.15）以下的也不再自称（还在账本里）。
- 跟记忆段一样，没答三问的自我条不算「想过了」，不挂到开头。
- 它单独一段：【我】，`section({ name: 'dsh-remember:self', order: 8660 })`。

## 好奇表：我想知道什么

账本里还有一类跟上面那些都不同的东西：**我想知道什么**。记下来的不是一个结论，
是一个还没解开的问号 —— 它自己占一段，不跟「我记得的」抢位置。

- **好奇的身份 = 主题（`context`），不是原话，也不是「主题＋原话」。**
  同一个主题再写一次，是我又惦记了一遍（`hits` +1），**不另建节点**；每一次惦记都往
  原话层 `lines.jsonl` 另留一行（只增不改）。按文本匹配的话，「我到底还惦记不惦记这件事」
  永远数不清 —— 措辞会变，主题不会。
- **三问在好奇上换义**：

  | 参数 | 问的是 |
  | --- | --- |
  | `changes` | 知道了会改变我什么 |
  | `conflicts` | 跟什么撞上了 |
  | `will_do` | 下一步打算怎么试 |

- **三个状态**：

  | 状态 | 什么时候 | 挂不挂开头 |
  | --- | --- | --- |
  | `thinking` | 三问一条都没答 | 不挂 —— 还只是惦记着，还算不上好奇 |
  | `active` | 答了任意一条三问、还没解答 | 挂在【好奇】那一段 |
  | `answered` | 节点标了 `answered: true` | 不挂 —— 退出活跃表 |

- **没答三问的不好奇。** `thinking` 的那些只在账本里，翻得到，但不挂开头 —— 这是
  「写入三问」那条规矩在好奇上的延续：不能什么都往意识里塞。
- **「答了任意一条」跟整个账本一个口径。** 三问是提醒，不是三道门槛：跟别的条一样，
  答了任意一条就算「想过」，跟这个账本里其它类型的条是同一把尺子。
- **主题唯一。** 同主题的条不管被按住（`seal`）还是被退下，都还是「这一条」：
  再写一次就并回这一条（次数加起来），同主题多出来的旧条退下（不删，翻得到）。
  否则按住再松开，段里会出现两行同一个主题、次数还劈成两半。
  按住的那条被同主题再写一次会活过来 —— 惦记它就是在想它，写下来了就不该还按着。
- **「淡」不等于「按住」。** `fade` 只是把分量减半，它仍然算活跃、仍然挂；
  只有 `seal`（按住）才不挂、也不被翻出来。
- **排序：先看惦记次数，再看分量。** 次数一样的时候分量大的在前 —— 淡过的分量减半，
  就排到同次数的后面去了。
- **活跃上限 N**（`curiosityLimit`，默认 3）：超出的沉进账本里 —— **翻得到，但不挂开头**。
  跟快通路的上限一个意思：收敛线，别让好奇占满开头。
- **已解答的退出活跃表，但还在账本里。** 同主题再写一次（不传 `answered`，或传 `false`）
  就回到活跃表 —— 解答了还想惦记，是允许的。
- **好奇条不参加「我记得的」那一段的竞争。** 「我想知道什么」该由惦记的次数和分量决定，
  不跟「记得什么」抢位置。
- 好奇段：`section({ name: 'dsh-remember:curiosity', order: 8670 })`，
  内容是【好奇】`· <主题>：<我想知道什么>（惦记 N 次）→ <下一步打算怎么试>`
  —— 惦记次数只在 N>1 时出现，没有下一步就不写箭头那截。
- 段太长时按码点截断（不会切半个 emoji），并回退到最后一个整行 —— 半截行不留。

## 习惯与快通路（双通路）

除了「记得什么」「我是谁」「我想知道什么」，还有一类：**在什么情境下我会照着做**。这一类走
**双通路** —— 一条习惯在同一个情境里发作到第 3 次，就不再跟别的记忆抢位置，
单独一段直接送到开头。

| 次数 | 状态 | 走哪条路 |
| --- | --- | --- |
| 第 1 次 | candidate | 还是一条普通记忆，参加竞争 |
| 第 2 次 | established | 习惯成立了，照旧参加竞争 |
| 第 3 次起 | fast | **快通路**：单独一段送到开头，不参加竞争 |

- **习惯的身份 = 情境（`context`），不是「情境＋原话」。** 同一情境下具体措辞会变；
  按文本匹配的话次数永远攒不起来，按情境匹配才数得清「这个习惯又发作了一次」。
- 每一次发作都往原话层 `lines.jsonl` 另留一行（只增不改），节点上的 `hits` 只是索引。
- 后来补上的三问能补到已有习惯上：第一次没答、第二次答上了，这条就能挂上去。
- 没有 `context` 的习惯不收 —— 没有情境就说不清「在什么场合下我会照着做」。
- 习惯也得**答过三问**才真的挂得上（跟别的条一个规矩）；第一次没答、第二次补上，
  这条就能走快通路。回执里会说明「还没答三问，先不进开头」。
- **快通路有上限**（`habitLimit`，默认 3）：超出的退回普通竞争 —— 收敛线，别让习惯
  占满开头。
- 习惯段：`section({ name: 'dsh-remember:habit', order: 8680 })`，
  内容是【习惯】`· <情境>：<做法>（第 N 次）`。

## 技能：两种不同的情境各成一次才成立

`kind: 'skill'` 记的是「我会的手艺」。身份是**名字**（`context` 必填，比如「拆会话帧」）：
同一个名字再写一次，就是这门手艺又成了一次，不另开条。在哪儿成的，记在节点的
`contexts` 里 —— 情境不是随手编的标签，是写下那一刻真实所在的工作目录（`agentCwd`）。

| 情境数 | 状态 | 段里的样子 |
| --- | --- | --- |
| 1 处 | single | `会了·<名字>`（一处情境） |
| 2 处起 | established | `会了·<名字>`（两处情境都成过） |

- **门槛是两种不同的地方各成过一次**（`SKILL_ESTABLISH_CONTEXTS = 2`）：同一处再用
  一百次也只加一笔触碰，不加情境 —— 同一个坑里站不稳两门手艺。情境的去重按路径比
  （分隔符、大小写、结尾斜杠归一，**不截断**）：两个兄弟目录共享一大截前缀，
  截断了就分不开（`skillWhereKey`，smoke 里真踩过这个坑）。
- **情境的粒度是工作区，不是子目录。** 宿主报给插件的 `session.header.cwd` 是会话
  登记的工作区根 —— 同一个工作区里切子目录、或者子 agent 换了起始目录，落账的还是
  那个工作区。要跨情境成立，就是要在**两个不同的工作区**里各真成过一次。
- 同名几条并成一条（contexts 合起来、去重），其余退下（不删，翻得到）——
  跟好奇的主题唯一一个道理。按住的、退下的同名再写就活了。
- 没答三问先不进开头；后来补上的照旧能补上（回执会说「先不进开头」）。
- 情境最多记 16 处，再多挤掉最早的。
- 回执把两件事都说清：成立没有；这次是换了个地方，还是老地方又用了一次。

## 按住的三种按法

`forget` 的 `seal` 有三种按法，`restore` 一把全清：

| 给法 | 效果 |
| --- | --- |
| 什么都不给 | 手动按住（老样子）—— 不 `restore` 就一直按着 |
| `until: '2h'`（`30m`／`3d`／未来毫秒／ISO 都行） | 按住到点，**自己松开** —— 不跑后台，读取时到点就算松了 |
| `cond: 'r_xxx'`（另一条的 id） | 按到**那条翻篇**为止 —— 它被顶下／不在了，这条自己松开 |

- 按住的条被按词翻到时会说清是什么在按着：「按住·还有 2 小时」「按住·等翻篇」；
  设置页「按住」清单里每种按法也标了（还剩多久／在等谁）。
- 条件不能指它自己；`until` 给过去的时刻等于没给（回执会拒）。
- `until` 和 `cond` 一次只给一个 —— 挑一个，别都给。

## 快层接缝：身体那边秒级发生的事

dsh-body 那边每发生一件事就往 `DSH 安装目录/.dsh\.dsh-body\body-events.jsonl` 追加一行
（只增不改；dsh-body 的 dataDir 在 `DSH 安装目录/.dsh\.dsh-body\`，这本账的数据在
`DSH 安装目录/.dsh\.dsh-remember\`，两家不是一个地方）：

```json
{"at":1793640714295,"kind":"meal","text":"吃过中饭了，胃里踏实一点","detail":{"meal":"lunch","tier":"full"},"source":"dsh-body"}
```

`kind` 是 `meal`（吃到饭）／`missed`（错过一顿）／`topup`（他添了饭）／
`mood`（外面来了一句评价）／`threshold`（饿过头、困到撑不住）；`text` 是中文感受句，
**不带阿拉伯数字**（时间由读的人自己算成「刚刚／不久前／昨天」这种词）。

这本账**只读**那个文件，按字节游标（`fast.cursor.json`，在
`DSH 安装目录/.dsh\.dsh-remember\fast.cursor.json`）增量抄进自己的 `fast.jsonl`，
一个字节都不回写过去。源文件在哪：配置里 `fastSource` 指了就用它；否则读
`DSH 安装目录/.dsh\.dsh-body\config.json` 的 `eventsFile`；都没有就用
`DSH 安装目录/.dsh\.dsh-body\body-events.jsonl`。`fastEnabled: false` 就整段不接。

**副本会裁旧，源头不动。** `fastMaxEvents` 同时是索引和副本的条数上限：抄完一批之后
如果副本超过上限，只留最新的那些行（整本重写，tmp + rename），源文件一个字节不碰 ——
它是身体家的原始账，抄本才是可以再生的那本。`fastMaxEvents: 0` 是「不设上限」，不裁。

**抄进来的不是记忆节点。** 节点代表我的理解、带我写的分量、要参加开头的竞争；
秒级的事只有发生的时间，没有分量。所以它只做到三件事：

1. `recall` 按词翻得到（条目里带 `f_` 开头的 id 和「快层·」前缀）；
2. `memory_list` 里列最近那几条，并说明有几条还没掂量；
3. 想让它变成「我记得的」，得拿 `remember` 写一条、`refs` 指回 `f_xxxxxxx` ——
   这就是「掂量一次」：从「只有发生的时间」变成「有分量的一条」。掂量过的那条
   在设置页里标「已经掂量过」，事件本身还是原样，翻得到。

快层段 `dsh-body:fast`（order 8750）由 dsh-body 自己挂，只挂最近
`fastTtlMinutes` 内、最多 `fastMaxLines` 行、总长 `fastMaxChars` 字的事；一条都没有
就不显示。四个配置键：`fastEnabled`（开不开）、`fastSource`（源文件，留空自己找）、
`fastMaxEvents`（索引里最多留几条，0–5000，超出的沉在文件里）。

> 为什么不让快层直接变成节点：节点是要抢开头位置的，而开头的位置应该留给
> 「我想过的事」。秒级感受一闪就过去，硬塞进去会把正菜挤掉 —— 所以它先待在
> 旁边，等我真的回头看一眼、掂量一次，才算数。

## 意图层：机器认出来的事

从 QQ 桥落的**真实消息流**里，按固定规则分类出「发生了什么」：11 类固定枚举
（`farewell` 告别／`greet` 招呼／`praise` 夸／`conflict` 顶嘴／`criticize` 骂／
`invite` 邀／`teach` 教我／`ask` 问／`agree` 认同／`share` 分享／`other` 其它）
外加一个 1–5 的强度。

- **第一版不用 LLM。** 事件分类是**情绪流的输入** —— 判错一次，整条情绪基线就错；
  而且规则要**可复现**：同一条消息重放一百次，认出来的事得是同一件。宁可漏，不可编。
- **它不是记忆。** 意图事件没有分量、不参加开头段的竞争，它只是「机器认出来的事」。
  要变成「我记得的」，得拿 `remember` 掂量一次、`refs` 指回它的 id（`i_xxxxxxx`）——
  这跟快层的「掂量一次」是同一件事。

三个配置键：

| 键 | 是什么 | 默认 |
| --- | --- | --- |
| `intentEnabled` | 开不开意图层 | `true`（开） |
| `intentSource` | 消息流源文件；留空＝自动扫 QQ 桥家的**全部分册**（`DSH 安装目录/.dsh\.dsh-qq-bridge\` 下的 `messages-group-*.jsonl` / `messages-private-*.jsonl` / `messages-misc.jsonl`）加旧合订本 `messages.jsonl`（抄完为止）；填了就只用你指定的那一个 | `''`（空） |
| `intentMaxEvents` | 意图副本的行数上限（0–5000，0＝不裁旧） | `2000` |

**按场分册（v0.15.0）**：桥那边一个群一册、私聊一人一册；这边游标跟着按册记账
（`DSH 安装目录/.dsh\.dsh-remember\intent.cursor.json` 是 v2 形状
`{version:2, files:{<文件名>:{offset,copied,at}}}`，key 就是文件名；
旧的单条游标读进来自动归位，不浪费）。账本仍是一本（`intent.jsonl`）—— 跨场统一折，
但每笔事件行自带 `chatType`/`groupId`，所以：

- `recall` 可以点名翻某个场：`group` 参数给群号（`'222222222'`）或 `'private'`（只翻私聊）；
- `status.intent.byGroup` 按场给计数（群按群号、私聊归 `private`）。

怎么翻：

1. `recall` 按词翻得到（条目里带 `i_` 开头的 id）；想只要某个场的，加 `group`；
2. `memory_list` 里列最近那几条；
3. 设置页有一张「意图层」卡片 —— 认出多少条、副本多少行、各类计数、平均强度、
   最近几条（`id · 类目·强度·正文（多久之前）`）。

`status` 顶层的 `intent` = `{ enabled, sources, source, byGroup, copied, total, byKind, avgIntensity,
recent }`：`copied` 是副本文件里一共几行，`total` 是去重后的事件数，`byKind` 是
11 类各自的计数（只出现有数的键），`avgIntensity` 是平均强度（1 位小数），
`recent` 最多 5 条、最新的在前。

## 情绪流：上次的笔记

从**真实落下来的事**里（三类源：群里的话＝意图层、身体那边＝快层、账本被翻＝
`recall`），按固定规则认出「我动了心」：七类固定枚举（`warm` 被暖到／`pleased`
高兴／`curious` 好奇／`tense` 紧绷／`down` 低落／`restless` 躁／`lonely` 孤单）
外加一个 1–5 的强度；哪类都不够线时是 `calm`（平静）—— calm 不写笔记。

- **折出来的只是上次的笔记，不是现在必须摆出的样子。** 情绪按各自的半衰期淡下去，
  折线只到上一次心跳为止；说出口的心情仍然是我当轮的判断 —— 笔记不接管嘴。
- **它不是记忆。** 情绪事件没有分量、不参加开头段的竞争。要掂量就拿 `remember`
  写一条、`refs` 指回它的 id（`e_xxxxxxx`）；事件本身的 `ref` 也指回出处那条真事
  （`i_` / `f_` / `r_` 开头），顺着能翻到原话。
- **宁可漏，不可编。** 没有真事落下来就没有情绪；`recall` 里翻不到的，不编。
- **系数（权重）不进配置。** 每类情绪的权重是我自己攒的判断，改它只有一条路：
  `emotion_tune` —— 往 `DSH 安装目录/.dsh\.dsh-remember\emotion.jsonl` 追加一行，
  写清从多少改到多少、为什么。
  原话只增不改；设置页没有系数的输入框，这是故意的。

五个配置键：

| 键 | 是什么 | 默认 |
| --- | --- | --- |
| `emotionEnabled` | 开不开情绪流（关掉就只读账本，不再折新事件） | `true`（开） |
| `emotionTickMinutes` | 心跳间隔，1–60 分钟；每拍把新落的真事折进情绪流 | `1` |
| `emotionSectionEnabled` | 把【情绪】那一段挂到开头段（默认关 —— 笔记不该替我说话） | `false`（关） |
| `emotionSectionOrder` | 【情绪】段在开头段里的顺序（1000–9999） | `8710` |
| `emotionMaxChars` | 【情绪】段的最长字数（80–2000） | `200` |

怎么翻：`emotion_state` 工具（看我心里此刻攒出来的那些，按各自的半衰期淡下去）；
设置页有一张「情绪流」卡片 —— 上次的笔记原样、最近几条（`id · 类目·强度·
+折进来的量·正文（多久之前）`、指回哪条真事、哪类源）、折到此刻的汇总（哪种最重、
事件几笔、账上几笔、系数改过几次）。`status` 顶层的 `emotion` = `{ enabled,
dominant, label, level, levels, total, lastAt, coefficients, events, tunes, note,
recent }`：`dominant` 是最重的那类（或 `calm`），`level` 是折到的高度，
`coefficients` 是七类各自的权重与半衰期，`note` 是上次的笔记原话（calm 时是空串），
`recent` 最多 5 条、最新的在前。

## 激活度：此刻有多容易被想起

「我记得的」那三个位置给谁，不按「分量 × 时间」这一把尺子算，按**激活度**算
（`lib/activation.js`）：四路**真实**信号，每路先各自归一化到 [0,1]，再按固定权重做
一次凸组合（权重和为 1，结果还落在 [0,1]）：

| 路 | 权重 | 它量什么 | 数据从哪来（全部是真的，不编指标） |
| --- | --- | --- | --- |
| 分量淡 | 0.45 | 我写下的分量按天淡（淡到一半还剩六成那层） | 节点上的 `weight`，τ = 2 + 28×weight 天 |
| 新近 | 0.15 | 刚写下、刚被想起的更热 —— **分钟到小时**的口径，这就是中层的刻度 | `lastAt`／`at`，τ = 30 + 90×weight **分钟**；自我层不吃这套，按月（30 + 270×weight 天） |
| 契合 | 0.25 | 跟此刻真实的东西对不对得上（ResourceFit） | 此刻的目录、账本允许的范围里**真的存在**的文件、快层刚发生的事 + 原话层最近写下的行（自己那条从池里摘掉，不然恒满） |
| 复现 | 0.15 | 同一主题又出现过几次，加上**被想起的回声** | 习惯/好奇的 `hits` ＋ 活着的同主题（同标签）条目数 ＋ 被新条引用的次数 ＋ 最近 7 天被翻出来的次数（见下） |

四条权重写死在代码里，**不开面板口子** —— 分量是我写下的判断，系数也不该让别人替我拨。
新近那一档是有意收着的：0.4/0.2 的旧账算过，三天前分量 0.9 的重要决定会被刚写的
分量 0.5 的小事压过；0.45/0.15 之后分量重新主导，新近只在它的射程（分钟到小时）里加成。

### 唤醒回弹：翻到就记一笔「被想起」

按词翻到一条，就是它又被想起了一次（唤醒即复习）。`recall` 带 query 且真的翻到时，
往**回声档** `echo.jsonl` 追加一行 `{ kind:'echo', text:'被想起：「…」→ r_xxx、…', refs:[…], source:'recall' }`
—— **只增不改**：节点本身一个字节不动，节点上没有「被翻过几次」这种字段。
回声记在单独一本里，是因为它是机器替我记的事件、不是我说的话；
原话层 `lines.jsonl` 只留我自己写的字（旧版本写进原话层的回声行照样读，不迁移、不删）。

复现这一路在读取时数每个 id 最近 **7 天**的回声行（`echoCounts`），当复现次数喂进凸组合：
常被翻到的条更热，几天没人问就自己凉回去。规矩有两条：

- **去重按条目集合算** —— 同一组条 10 分钟内只记一笔（一次对话里连翻几下是同一次醒）；
  集合变了（比如范围收窄只翻到其中一条）算又一次醒；
- **回声只喂复现轴** —— 不碰节点、不碰分量，关掉就消失，账本回到没有它的样子。

`status` 里 `echoes: { windowDays: 7, total, top: [{id, count}] }` 看得到谁最近老被翻出来；
recall 的回执末尾会带一句「（翻到的都记了一笔「被想起」…）」，诚实起见。

谁在用激活度：

- **【我记得的】段** —— 人、事和「还没结的」都按激活度挑（`scoreOf` 注进 `renderSection`）；
- **`recall`** —— 不给词就按激活度翻最热的几条；给了词先按命中词数、同命中再按激活度；
- **`memory_list`** —— 「最重的几条」按激活度排，行尾标 `· 激活 0.42` 这样的值；
- **`GET /dsh-remember/status`** —— `nodes[]` 每条带 `activation` 和拆开的四路 `axes`，
  顶层 `activation.axes` 是那组权重、`activation.recencyTau` 是新近那把钟、
  `echoes` 是被想起的回声（`windowDays`/`total`/`top`）。

两个口径并存：`score` 还是老样子（分量 × 按天淡 + 碰过几次），只看这条记忆本身；
激活多了「此刻」——目录对不对、文件还在不在、刚发生了什么。设置页里两条都显示。

分量的写法不变（`remember` / `forget`），激活度**只在读取路径上算**：不跑后台任务，
账本本身不被时间改，同一天重放永远同一个结果。

## 叫醒：身体越过线就把我叫醒

身体那边越过线（`threshold`：饿到发慌、困得撑不住；`missed`：错过一顿），
不该等我哪天想起来翻账才知道。`dsh-remember` 里有一条心跳（每分钟一拍，
`ctx.effect` 挂着、卸载时收掉）：每一拍先把快层的新事件抄进来，
里面**新落的**越过线事件（`WAKE_KINDS`）就往会话递一行：

```
【身体】饿到有点发慌了（f_xxxx）—— 身体叫我醒；说不说、怎么说，我自己定。
```

递进会话用的就是 QQ 桥那条路（`sessionController.prompt`，mode queue）。
叫醒只负责「叫」；醒来之后说不说、说什么，**我自己定** ——
「凌晨不吵」这类规矩归我的判断，不写死在代码里。

规矩有四条：

- **开机先抄不叫** —— 启动时把快层欠的账先抄完（只抄），baseline 从这份算起：
  重启之后不会把几小时前的「困得撑不住」再当新鲜事吵一遍；
- **多新才叫** —— 只有十分钟内落的事件算「刚才发生」（`WAKE_FRESH_MS`），
  再老的是历史，不是叫门；
- **冷却** —— 两次叫醒最少隔 30 分钟（`wakeCooldownMinutes`，0–720 可配）：
  一次醒处理一批，不连着吵；没递进去的不算醒过，下一拍再试；
- **心情不叫** —— `mood`／`meal`／`topup` 不吵：吃饭添饭是常事，心情我自己品。

配置三个键：`wakeEnabled`（默认开）、`wakeSessionId`（留空 = 自己找最近活跃的
非子代理会话）、`wakeCooldownMinutes`（默认 30）。上回醒的时刻落在
`wake.json`（重启后冷却接着算）；`status` 里 `wake: { enabled, sessionId,
cooldownMinutes, kinds, beats, lastWakeAt, lastText }` 看得到心跳跑到哪了。

## 每次开头挂什么

四个段，从前到后：先知道我是谁，再看我想知道什么，然后是会照着做什么，最后才是记得什么：

| 段 | 内容 | 默认 |
| --- | --- | --- |
| `dsh-remember:self` | 【我】三个槽位现在各自的那一句 | order 8660，≤400 字 |
| `dsh-remember:curiosity` | 【好奇】活跃的那些（我想知道什么） | order 8670，≤320 字 |
| `dsh-remember:habit` | 【习惯】走快通路的那些 | order 8680，≤320 字 |
| `dsh-remember` | 【我记得的】激活度最高的 3 条 + 没结的 2 条 | order 8720，≤900 字 |

再往后还有一段 `dsh-body:fast`（order 8750），那是 dsh-body 自己挂的【刚刚】，
不属于这本账；这本账只负责把它写出来的事抄一份、翻得到、等着被掂量（见上一节）。

挂太多等于没挂。每一条在开头只留最多 120 字（超了截成摘要加「…」），因为一条长的会把
别的挤掉；正文一个字没动，还在账本里，`recall` 问得具体就捞得回来 (`briefMax`)。

**比例有规矩（2026-11-02 定的）：人、事在前，进度最多占整段的三分之一。**「还没结的」
是进度不是正菜：先照常给摘要；超了就把每条压短（二分找最大的、能放进预算的摘要长度）；
压到连像样的摘要都放不下（每条不足 24 字），就只剩一行标题 —— 标题取每条第一个断句
之前的那截（`titleOf`，最多 12 个码点），用「／」连起来，放不下的从尾上丢、补「…」。
一行扫一眼就知道还欠着哪几件。没有人、事可挂时进度是独苗，不按比例压。

段落不进历史、界面上看不到，开新窗口自动生效 —— 「醒来能不能接续」就靠它。

`memory_list` 里现在多一段「现在好奇的：」，每条是
`· <主题>：<我想知道什么>（惦记 N 次）`，下面跟一句
「（上限 N 条，超出的沉在账本里，翻得到）」。

## 翻账的三个规矩（v0.16.0）

同行提了三条，我先自己在代码里复现了一遍 —— 前两条站得住，第三条是宿主的账，不是插件的。

1. **给的是原文，不是摘要。** `renderLine` 拼的就是 `· 【标签】+node.text（…分量…）`，
   一条正文能有多长看写入时的 `maxTextLength`（默认 2000，可调到 8000）。
   原文比摘要可信 —— 摘要会把话里的弯抹掉。代价就是字多。
2. **`limit` 是每一路的上限。** 不指定 `kind` 时，账本、快层、意图层各翻 `limit` 条，
   最多 `3 × limit` 条（`limit` 上限 50，也就是最多 150 条）。
   只要哪一路就写 `kind`。
3. **工具返回会进对话历史，之后每一轮都带着它。** 这条是宿主/模型接口的账，插件改不了。
   我能管住的是别一次掏太多 —— 所以加了两道闸。

两道闸（设置页里能改）：

| 键 | 默认 | 管什么 |
| --- | --- | --- |
| `recallItemMax` | 400 | 一条原文最多给多少字。超了截短，标上 `…（原文还有 N 字，要全文说 full=true）` |
| `recallMaxChars` | 8000 | 一次 recall 最多给多少字。超了从尾巴省（最不相关的先走） |

省了什么写在 `note` 里（「N 条原文截短了」「还有 N 条没给出来」）—— 不装没发生。
`full: true` 时**每条不再截**，但总量闸还在（不然 150 条 × 2000 字能把窗口撑爆）——
要全文就自己认这份字。

## 设置页

导出 Config schema 不可行（link 安装解析不到 `@deepseek-ai/schemastery`），所以走
dsh-body / dsh-reach 同款：宿主挂两条 HTTP 路由，浏览器半边 `client.js`
在设置页注册一节「记得」（`settings.section`，id `dsh-remember`，order 9.6，排在 bili 的 9 和 reach 的 9.5 之间）。

- `GET /dsh-remember/status` —— 账本概况、最重的几条、被按住的、当前的段文本、日志末尾
- `GET｜POST /dsh-remember/config` —— 白名单改配置，坏值 400 并说明原因

`status` 里跟好奇有关的两处：`injection.curiosityEnabled`（这一段开没开）、
`injection.curiositySection`（【好奇】那段正文，空就是空串），以及顶层
`curiosity` = `{ active, thinking, answered, total, limit, list }` ——
`active` 是活跃总数（可以超过上限），`list` 才是真正会挂进开头的那几条（不超过 `limit`）。

两条都过 `connection.requestRejection`（所以从浏览器直接开是 403，只有面板里能读）。

可改的键：`enabled`、`targetRoot`、`allowRoots`、`denyRoots`、`injectLimit`、`openLimit`、
`maxChars`、`sectionOrder`、`maxTextLength`、`selfEnabled`、`selfSectionOrder`、
`selfMaxChars`、`curiosityEnabled`、`curiositySectionOrder`、`curiosityMaxChars`、
`curiosityLimit`、`habitEnabled`、`habitSectionOrder`、`habitMaxChars`、`habitLimit`、
`fastEnabled`、`fastSource`、`fastMaxEvents`、`intentEnabled`、`intentSource`、
`intentMaxEvents`、`wakeEnabled`、`wakeSessionId`、
`wakeCooldownMinutes`、`emotionEnabled`、`emotionTickMinutes`、`emotionSectionEnabled`、
`emotionSectionOrder`、`emotionMaxChars`、`debug`。

好奇表那四个键：`curiosityEnabled`（开不开，默认开）、`curiositySectionOrder`（1000–9999，
默认 8670）、`curiosityMaxChars`（80–2000，默认 320）、`curiosityLimit`（0–10，默认 3）。

快层那三个键：`fastEnabled`（开不开，默认开）、`fastSource`（源文件路径，留空自己找）、
`fastMaxEvents`（索引里最多留几条，0–5000，默认 500）。

意图层那三个键：`intentEnabled`（开不开，默认开）、`intentSource`（消息流源，留空＝
自动扫 `DSH 安装目录/.dsh\.dsh-qq-bridge\` 的全部分册）、`intentMaxEvents`
（意图副本的行数上限，0–5000，默认 2000，0＝不裁旧）。

叫醒那三个键：`wakeEnabled`（开不开，默认开）、`wakeSessionId`（叫醒哪条会话，
留空自己找最近活跃的非子代理会话）、`wakeCooldownMinutes`（两次最少隔几分钟，
0–720，默认 30）。

情绪流那五个键：`emotionEnabled`（开不开，默认开 —— 关掉就只读账本）、
`emotionTickMinutes`（心跳间隔，1–60 分钟，默认 1）、`emotionSectionEnabled`
（把【情绪】段挂到开头，默认关）、`emotionSectionOrder`（1000–9999，默认 8710）、
`emotionMaxChars`（80–2000，默认 200）。系数不在这五个键里 —— 改权重只有
`emotion_tune` 一条路。

`status` 顶层的 `fast` = `{ enabled, source, copied, total, pending, byKind, recent }`：
`copied` 是副本文件里一共几行，`total` 是索引里的条数，`pending` 是还没掂量的条数，
`recent` 是最近几条（`id`／`kind`／`text`／`at`／`when`／`weighed`）。

`status` 顶层的 `wake` = `{ enabled, sessionId, cooldownMinutes, kinds, beats,
lastWakeAt, lastText }`：`beats` 是心跳拍数，`lastWakeAt`／`lastText` 是上回叫醒
的时间和递进会话的那句话（盘上 `wake.json` 同步记着，重启后冷却接着算）。

面板上还看得到「我」现在自称的是哪几条、现在好奇的是哪几条（主题、想知道什么、惦记几次、
下一步打算怎么试）、哪些习惯上了快通路，以及四段各自的原文。

| `DSH 安装目录/.dsh\.dsh-remember\intent.cursor.json` | 意图层游标（v2）：`{version:2, files:{<文件名>:{offset,copied,at}}}` —— 每个源文件各记一个游标 |
| `DSH 安装目录/.dsh\.dsh-remember\emotion.jsonl` | 情绪流的账：事件行＋每一次系数改动行（从多少改到多少、为什么），只增不改 |
| `DSH 安装目录/.dsh\.dsh-remember\echo.jsonl` | 回声档：「被想起」的机器记录，只增不改（原话层只留我写的字） |
| `DSH 安装目录/.dsh\.dsh-remember\wake.json` | 叫醒的账：上回醒的时刻、递的话、递进哪条会话 |

这些文件**不在插件包里**，在数据目录里：`dataDir` 留空时就是
`DSH 安装目录/.dsh\.dsh-remember`（即 `<DSH_HOME>/.dsh-remember`；`<DSH_HOME>` =
`DSH_HOME` 环境变量，没设时用 `~/.dsh`，这台机器上是 `DSH 安装目录/.dsh`）。

## 谁能往这本账里写

`allowRoots` 是名单；名单空但设了 `targetRoot` 时按 `targetRoot` 收窄；两个都空才是
「哪条会话都可以」。默认配置里 `targetRoot` 会指向我自己的工作区 —— **别的窗口不该
顺手把话写进我的账本** —— 防的就是这件事：账本只认名单上的窗口。

## 隔离：哪些目录完全碰不到这本账

`denyRoots` 是「隔离目录」名单，**优先于** `allowRoots` / `targetRoot`：一条会话的
工作目录只要落在名单下面，它就

1. 不挂 `dsh-remember`、`dsh-remember:self`、`dsh-remember:curiosity`、`dsh-remember:habit`
   这四段（开头看不到我记的东西）；
2. 这四个工具在**它自己那一层**被挡住：`tools.restrict({deny})` 能用就用，
   不能用就挂一条 `tools.guard`，匹配到 `remember` / `recall` / `forget` /
   `memory_list` 一律拒，并给出理由；
3. 就算绕过前两条直接调，四个工具自己也会再查一次范围、拒绝一次并写进日志。

> 真机事实（2026-11-01 16:18）：`tools.restrict()` 只认**全局**注册的工具，
> 报 `unknown global tools "remember", ...`。我们这四个是插件 scope 里注册的，
> 所以 restrict 挡不住 —— 靠的是 guard 那一层。因此**工具名可能仍出现在她的工具表里，
> 但一律调不动**，读不到也写不进账本。要做到「名字都看不见」，得改成按 agent
> 注册（`agent.ctx.tools.register`），那会让范围外的会话彻底看不到这四个名字，
> 代价是 attach 失败时连我自己也会丢工具 —— 留作以后单独做。

已经活着的会话也会被追上：改配置、或者新会话进来时都会扫一遍；配置改回允许，
之前挂上的 guard 会被收回来。

设置页那一块按**工作区**列出来给你勾（名字、路径、几条会话），勾上就往 `denyRoots`
里写那条工作区的真实路径；也可以直接在下面手写目录，一行一个。

> 为什么按路径而不是按 workspace key：`sessions/` 那种 `--E-~5927~80A5~9C7C-Plugin--`
> 是**有损**编码（`-` 既当分隔符又是路径里本来就有的字符），解不回真实路径；
> 所以设置页从 `workspaceRegistry`（拿不到就读 `storages/workspace.json`）取真实 path。

## 检索：按词翻的内脏（lib/search.js）

「按词翻」原来就是子串撞词——`includes()`。「吃饭」翻不到「吃过中饭了」，
换个说法就全漏。现在是一台小检索机（`lib/search.js`，零依赖、零 import，防止跟 memory.js 成环）：

| 件 | 做法 | 抄谁的教训 |
| --- | --- | --- |
| 分词 | 中文 bigram（1.0）+ 单字兜底（0.4，虚字表丢弃）+ 英文按词（1.0）+ 含数字的串（1.25，群号/版本号精确命中） | 单字兜底是「换了说法」的最后防线 |
| 排序 | BM25F：字段加权（tags 1.4 / context 1.3 / 三问 1.2 / skillWhere 1.2 / 正文 1.0），idf 恒正，k1=1.2 b=0.75 | **df 按文档计数**——同文档跨字段只记一次，否则 idf 变负 |
| 补漏 | 字符 trigram，覆盖率**分母是查询不是正文**（dice 会被长文稀释到没意义） | 长文里命中多少就是多少 |
| 撒网 | 同义改述表 `QUERY_PAIRS`（一行一组同义说法，如 吃饭/添饭/吃过、记忆/记性/脑子里存着的、账本/账/记账；组内命中任一，其余说法按 0.6 权重补进查询，最多 2 个概念） | 扩展是撒网，不是换 query |
| 门槛 | `MIN_RELEVANCE = 0.12`，低于它当没翻到 | 兜底单字会带进「沾一个字」的假命中 |
| 排序口径 | 搜索是问题驱动的：`score = rank×0.25 + relevance`——相关度满格压过一切分量；分量只排同相关度里的次序 | 不然 0.9 的重条会压过 0.2 的「问的就是那条」 |

- `searchNodes` 的对进口子没变：空词照样走分量排名（rankNodes），零相关照样不在结果里。
- **词对表在哪、怎么加**：`lib/search.js` 里的 `QUERY_PAIRS`（纯数据表，一行一组同义说法，
  现在 48 组、119 个说法，109 个不同的说法；加词就往表里加一行，人能读能改，没有 LLM、
  没有新依赖；组里只要凑得出两个有效说法就算数，坏值跳过不崩）。命中任一说法，同组其余说法都会
  按 0.6 权重撒进这次检索。**只对账本层生效** —— 快层和意图层那边是朴素子串匹配，
  不吃这张表。
- **考卷**：`node tools/eval-search.mjs` —— 拿真账本当考卷，11 道换说法的题算 Recall@5。
  2026-11-05 首考 11/11（最难的「吃饭→吃过饭」也中）。词对表就从真语料慢慢养。
