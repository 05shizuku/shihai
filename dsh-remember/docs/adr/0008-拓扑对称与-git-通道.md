## Plugin\ 旧装载位（墓碑语义）

`E:\大肥鱼\Plugin\dsh-qq-bridge`、`E:\大肥鱼\Plugin\dsh-she` 两个 junction 保留，仍指仓内
同目标（hash 一致）。现役负载不走它们（宿主走 profiles\desktop\node_modules），但 amikar
侧门（gate.mjs 的 GATE_PLUGIN_DIR=E:\大肥鱼\Plugin、_say.mjs）邻接此目录工作——**不删**。
墓碑的语义 = 「曾几何时运行体在这里，现在仓在 E:\大肥鱼\shihai，这两个链接只是历史通道」。

## 认仓公理（g15 §4，重申）

**运行体 = git 仓 = 版本控制对象。** 装载位通过 junction 指仓，所以：
1. 改仓即改运行体（junction = 热改在役器官，git 操作纪律见 g15 §2）；
2. 「服务层拿同一个核」在拓扑上已成立——G-2 的 service/ 读的是同一份仓内文件，
   无需复制代码（这是「给骨架不给家」的文件系统面）；
3. 任何「从运行位拷一份出来改」的动作都是制造分叉，禁止（normPath 三实现的教训同源）。

## git 通道

- PATH 无 git。实际通道 = GitHub Desktop 内嵌 git：
  `C:\Users\10113\AppData\Local\GitHubDesktop\app-3.6.11\resources\app\git\cmd\git.exe`
- push 500 解法：`--no-thin`（2026-11-25 实证入档，g15 §2）。
- 提交/推送由维护者执行；执行者（lead/amikar 侧）只改工作树与暂存，不 commit 不 push。

## 对 G-2 的含义

服务化（G-2 施工稿）**不改变本拓扑**：service/server.mjs 与九工具命令层读同一份仓内文件，
账本同源、单实例非接管式 claim（施工稿 §0.7 审旗①）。「关 DSH 验收」= 服务进程独立跑
12741，与宿主插件（inline 模式）不得同 dataDir 同跑——拓扑不变，约束写进契约。
