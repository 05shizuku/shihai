# ADR-0006 读路径性能纪律

状态：已采纳（2026-11-13，灯案 43 秒 /status 的教训成文）

## 背景

设置页 hub 每 5 秒拉一次 /status；唤醒心跳每分钟跑 buildStatus。
一次「循环内读全量文件」（noteEmotion 每次全量 parse 4MB emotion.jsonl，
对 ~80K 意图事件逐条调）让 /status 从毫秒涨到 43-87 秒，占满浏览器连接池，
把 body/bridge 的灯全饿死。

## 决定

1. **status 一律从内存索引聚合**，禁止读文件（vikarmaAgg、echoAt、
   latestEchoRow、sproutTracker、displayDays……同源同写，写入点即维护点）。
2. **循环内禁止调用「读全量文件」的函数**——读一次、传参复用（r_t93uzp 教训）。
3. **读侧聚合能缓存就缓存**：瀑流段同 UTC 日缓存一日（数据源过完昨日就不再变，
   缓存到日界安全）；display 天集 14 天窗自剪。
4. 新索引必须「写入点顺手维护」，不许为观测整本扫。

## 工程契约

- buildStatus 开头的 pull*（fast/intent/emotion）只抄字节游标增量。
- 性能钉在测试里：2 万行 echo 数据 buildStatus < 100ms（memory.test）；
  新增读侧逻辑必须带等价钉。
- 状态推导单点：deriveStandingBodyStates 只住 lib/fast.js（msOf/missedCount 的
  教训——状态语义不许两处各写一份）。

## 与识海哲学的关联

恒审思量的前提是别把当下卡死：识海要秒级在线，读路径一卡，
「念念不住」就成了「念念排队」。性能纪律是瀑流不淤的河道工程。
